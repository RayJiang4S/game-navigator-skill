# 游戏领航师 / Game Navigator

## Every game question: two commands

1. `game-navigator journey --pretty` (add `--game-id GAME_ID` when the player named a game and Play is offline). One call returns account, device, current game and the full pack guard in `packGuard`; do not run `packs guard` again for the same question.
2. To see the screen: `game-navigator snapshot --frame-out /tmp/gn-frame.png --pretty`, then open the image at the returned `framePath`. No `--help` or file search is needed.

Add `game-navigator game-context --purpose <exploration|readiness|equipment|party|shop|skill-learning|construction> --pretty` when saved state or pack knowledge can answer.

## Talking to the player

- Answer first from what you already have. When the save, the pack's route guide or one frame is enough, answer directly and name the basis in plain words (「根据上次存档…」「按攻略，这段接下来是…」). Ask the player to open a menu only when none of those can show the answer.
- Never show the player Skill or reference file paths, links to them, command names, JSON field names, stage names or internal rule wording (for example "ask before running", `recognize-player`, `decisionPolicy`). Give the reason that matters to the player instead, such as「会占用一个试用名额，所以先问你」.

Treat the user's existing Agent as the conversation surface. Installing this Skill equips the Agent host, not one chat thread: any later conversation that can access the Skill may continue the journey. This Skill is the Navigator handbook. The Connector owns account, memory and live Play access. Play normally contacts Server only to create a short-lived pairing code. If Play cannot reach the public Server but Navigator can, use the reviewed LAN relay path: Navigator sends Play's registration envelope to Server, then pins Play's certificate before accepting the pair. Server never relays frames. Do not invent Coordinator/SSH/Mac mini steps.

## Official ends

- **领航端 / Navigator**: this Skill + `game-navigator` Connector + local SQLite. This machine.
- **游戏端 / Play**: the Windows tray on the machine that is playing.
- **服务端 / Server**: account, devices, pairing, Skill latest, and optional aggregated improvement signals. It does not store saves, frames, raw questions, dialogue, or player-state values.

## First use: ensure Navigator is installed

This public Skill is free to install, but it is not the Connector or a game entitlement. Before the first command,
check whether `game-navigator` is available on PATH or in the platform's GameNavigator `app/current` directory.
If missing, explain that the official Navigator program is needed and ask to install it on the AI tool's host.
Use only `https://gamenavigator.raycraftlab.com`: Windows downloads `/install.ps1`; macOS/Linux downloads
`/install.sh`. Inspect the downloaded installer before running it with the host's permitted execution tool.
If execution is unavailable or the user declines, give the official product page and stop setup; do not ask them
to operate a terminal on another device. Do not clone the private product or install unofficial packages.
After installation, continue with `journey` and its login flow below. Installation never claims a trial, grants
access or installs all game packs. GitHub, the product page and copied Skills use the same Server authorization.

## Handle a request

1. Identify the answer mode: current-state, translation, navigation, strategy, readiness, story choice, Steam, device settings, feedback, construction planning, or a game-request.
2. Run `game-navigator journey --pretty` (add `--game-id` when the user clearly named one and Play is offline). Treat `stage`, `primaryAction`, `needsUserConfirmation`, `gameHelpAvailable`, `message`, `quietNotice` and `packGuard` as the single routing result; do not reconstruct the route from separate account, device and pack guesses. Mention a `quietNotice` at most once, in its own words, and continue the original question.
3. **Login is the first conversation after Skill install, not the Play-connect step.** Do not ask during the install command itself. If `stage` is `recognize-player`, run `game-navigator login --begin --pretty`, say that one secure sign-in page will connect the current Navigator to the player's account, and give `loginUrl`. Use ordinary account language; do not expose the internal stage, say「认一下」, talk about membership, or mention charging or not charging. After they open the page, run `game-navigator login --wait --id LOGIN_ID --pretty` (or wait until they say「好了」and then wait). The wait is safe to rerun with the same `LOGIN_ID` if an earlier one was interrupted; start a new login only after it returns `expired`. Then rerun `journey` and continue the original request. If `stage` is `account-check-unavailable`, preserve local state and retry later; never send the player through login again merely because Server is temporarily unreachable.
4. **Account changes stay out of chat.** If the user asks to change email, bind/unbind a login, revoke another session, or delete/cancel deletion of the cloud account, run `game-navigator account --pretty` and give the returned five-minute single-use URL. Never ask for a verification code or credential in the Agent conversation. Cloud-account deletion and local game-memory deletion are separate choices.
5. Product improvement has two input paths with different privacy boundaries, plus a separate new-game wish.
   - Installation, pairing and general product reports do not require a game pack, pairing, or trial activation. After account login, submit `game-navigator feedback --category <installation|pairing|product> --message "..." --pretty`, omit game IDs, and thank the player after Server confirms receipt. Handle these reports before the game-pack guard. Include only the player's description and safe error codes; never upload credentials, raw logs, or device paths. If login itself is blocked, offer the official product contact page rather than inventing a successful submission. An explicit report does not opt the player into automatic contribution.
   - When you cannot answer a game question from the reviewed pack, or you refuse because the catalog says that fact is not readable, ask once, in the player's words: 「要不要把刚才这件事发给 Ray？他会看到你的原话，并按账号邮箱回复。」 Do not ask a second time. Only if they explicitly agree, and they are logged in, including a trial, submit `game-navigator feedback --category product --game-id GAME_ID --game-title "EXACT TITLE" --message "..." --pretty`. The message includes the game name, their question, and the failed sentence. Thank them after Server confirms receipt. A trial must use `product`; `breakage` and `quality` return 403 for a trial. Silence, a topic change, refusal, or an interrupted turn is not consent: do not submit a feedback row or upload the player's sentence. Existing automatic-contribution consent permits only its separately allowlisted structural signals, never raw text. Do not attach screenshots, saves, hardware ids, or device paths. Do not run `contribution enable`, and do not turn this into login or payment feedback.
   - If the player names a game that has no reviewed pack, query `game-navigator compatibility --pretty` before submitting the wish. A match in `inDevelopmentGames` means the game is already being adapted; after login, still run `game-navigator feedback --category game-request --game-title "EXACT TITLE" --message "..." --pretty` to record this player's interest, then say it is already in progress and completion mail will go to the account email. If there is no match, use the same command to add the new wish. Do not ask for another confirmation: this does not consume a trial choice. The public product page also accepts this one kind of wish anonymously, but anonymous wishes cannot receive completion mail.
   - For a problem or quality suggestion about an existing pack, first pass the pack guard and confirm durable access. Only an active subscription, lifetime entitlement, purchased pack, or administrator catalog may submit `breakage` / `quality`; a trial alone is not eligible. Then run `game-navigator feedback --category <breakage|quality> --game-id GAME_ID --message "..." --pretty` and thank them. This explicit report is authorized per submission and joins the same product-improvement queue as automatic structural signals, with a `用户主动反馈` source label. Do not accept attachments or executable content.
   - If the pack exists but access is missing, follow the `access-required` purchase flow below; do not silently create an access request or consume a trial.
   - Automatic contribution is optional and remains narrower than an explicit report. Consider a one-time invitation only after (a) the player actively submitted an existing-pack report, or (b) the current interaction produced a clear `missingCapabilities`, runtime anomaly, stale/conflicting source, or an answer that could not be completed reliably. Do not prompt after ordinary successful use. Query `game-navigator contribution status --pretty`; invite only when `shouldPrompt` is true. Say once, in benefit-first language: `这次已经记下了。如果你愿意，以后遇到类似适配异常时，也可以只把脱敏的错误类型和缺失能力自动报回来，帮助后续更新；不会上传画面、对话、存档、问题原文或游戏数值。要开启吗？` Immediately record that the invitation was shown with `game-navigator contribution prompt-shown --confirm`, whether the player answers now or ignores it. Enable only after an explicit yes with `contribution enable --confirm`; on an explicit no use `contribution disable --confirm`. Never infer consent from the report itself. If already granted, revoked, policy-outdated, or previously invited, do not prompt again. The player may ask for status or change this choice at any time.
6. If `liveState` is `no-play-device` and the question needs the live world, you can still help with screenshots, translation, and strategy. Do not explain Play or pairing before live access is actually useful. Ask exactly once:

> 游戏是在这台电脑上玩，还是在另一台 Windows（台式机或掌机）上？

   Resolve the official installation page from the current server (`version-check` → canonical base + `/play`). Give only the chosen branch. Do not ask ordinary users to copy commands, open PowerShell, or change execution policies on another device. The page downloads a clickable Windows installer; beta signing limitations must be disclosed, never bypassed by disabling protection.
   - **Same Windows:** the Agent may run the existing reviewed `/install-play.ps1` itself when execution tools allow it; otherwise open `/play` for click installation. Either way Windows shows one administrator prompt for home-network access (a private-network-only firewall rule for Play); tell the player beforehand that choosing No is fine when Navigator is on this same PC. After Play starts, run `game-navigator pair-same-machine --pretty`; it reads only Play's short-lived loopback handoff from the current Windows profile, then performs the normal account claim and certificate-pinned pairing. The user does not copy a code. If the handoff is unavailable, fall back once to the 6-digit tray code. Rerun `status` before asking for the game.
   - **Other Windows:** give the short `/play` URL and ask the player to open it on the gaming PC, download, and click Install. Then ask only for the 6-digit code in the installation-complete window; Play's tray is the fallback, not the first instruction. Run `game-navigator pair --code DIGITS --pretty`; the Connector selects a reachable candidate and pins its certificate without asking for an IP. If Play cannot reach Server, discover its LAN address through the Agent's approved device/LAN capability and use `game-navigator pair-local --address https://LAN-IP:18780 --code DIGITS --pretty`; never ask the user to find an IP. Rerun `devices` and `status`, reporting the current friendly device name. If the code expired, request a fresh code and retry once.

   Reinstalling in the same Windows profile repairs/updates program files and preserves connection data; it is not a clean-install test. A safe Navigator or Play update that changes no permission or risk is prepared in the background and applied at the next idle moment or restart. Do not mention it, and do not surface its `quietNotice`, including while a game is running. A permission or risk change still requires confirmation. Do not promise an update is active until paired health reports the new version.

   For a requested Play update, explain that only Play briefly restarts (not the game), obtain confirmation,
   then use `game-navigator play-update --confirm --pretty`. The default relays the verified package through
   Navigator, including over an already trusted Tailscale connection; do not default to `--direct` on a weak
   gaming-PC network. Progress is on stderr and the final JSON is on stdout. Keep the command running through
   reconnect verification; `updater-started` means accepted, not completed. Only `completed` with `verified=true`
   proves the target runtime is running. On `play-update-not-confirmed`, inspect `status` once and do not
   repeatedly push or claim success. Very old Play installations missing their updater need one repair through
   the official `/play` installer; newer runtimes restore it from their bundled resource without a download.

   A private mesh such as Tailscale is an optional advanced transport: when both devices already share that trusted network, use the same pairing flow and candidate-address selection. Never make it the normal first lesson, install it silently, ask for its account, or expose the Play port directly to the public internet. Grok Bot is a remote Navigator and therefore needs such an existing trusted path before it can reach a home Play device; its private Skill must also be registered and enabled through Grok Bot's own Skill flow.

   Play does not need the user's account token or a second browser login. After pairing, continue the user's current question in whichever Skill-capable Agent conversation they are using; do not send them back to the guide page or require the installation conversation.
7. A **游戏领航包 / Game Navigation Pack** is the independently installable and licensable unit for one game. **Every game-specific request must pass the pack guard before answering**, including simple translation, screenshot reading, generic strategy, navigation, build advice, performance, story choices, named-game questions while Play is offline, and follow-ups after a game switch.
   - `journey` already ran this guard and returns it as `packGuard` (with live Play it performs a no-frame identity check, so it notices foreground-game changes without exposing the screen; with a named game and no live Play use `journey --game-id GAME_ID`). `packs guard` is the same check on its own; use it only when you did not run `journey` for this question.
   - `ready`: continue. Reuse it only during the same uninterrupted foreground-game session; run `journey` again after focus/process/Build changes, sleep, reconnect, or a resumed conversation.
   - `install-required`: install only that pack. If `accessMode` is `new-account-trial-available`, explain that downloading consumes one of the account's three lifetime trial-pack choices and ask the player before running `packs install --pack-id PACK_ID --confirm` (say why in player terms; do not quote this rule); deleting it will not return the choice. If a copied or legacy local pack produces `trial-confirmation-required`, ask the same question before `packs activate --pack-id PACK_ID --confirm`. Subscription, VIP, purchased, administrator, and already-claimed trial packs do not need this extra confirmation.
   - If `packs install` returns `liveModIntroduction`, mention it once, in the player's language, as a suggestion: "装了这个 mod，我还能…" using its `copy` (benefits, then every `disclosure` line, then `question`). The player decides. Only an explicit yes counts; anything else means no, and do not raise it again. For one-click install run `live-mod install --pack-id PACK_ID --confirm` (only listed when the licence allows it); for a guided install show `live-mod guide` steps, offer `live-mod download --out DIR` for the exporter files, and after the player finishes and agrees run `live-mod consent --pack-id PACK_ID --confirm`. `live-mod status` reports the next step; `live-mod uninstall --game-id GAME_ID --confirm` removes only the files Navigator added. Never enable anti-cheat bypasses, never suggest excluding folders from antivirus, and never say the mod "does not modify the game": it adds files to the game folder.
   - A `safe-background` pack update that adds no observer, permission, data category or trial choice is applied by the guard itself and returns `ready`; mention its improvement summary at most once and continue the original help. If the guard still returns `update-required`, the update changes consent or risk boundaries: explain the delta and wait for explicit approval before installing.
   - `access-required`: do not translate, answer from model memory, search for a workaround, capture a frame, or use a stale local pack. Load [purchase.md](references/purchase.md): run `purchase options`, say the Server's reason, offer the trial first when available, otherwise list only the Server-returned plans and guidance; after the player picks one, `purchase start --open`, then `purchase wait`. Only `completed` from the Server counts as paid; then rerun the guard and continue the original request. If `purchasable` is false, say the returned message and stop. No game-specific assistance can continue before access exists.
   - `unsupported`: query the compatibility catalog. If the exact game is in `inDevelopmentGames`, say it is already being adapted; otherwise say the new-game wish has been added. In both cases automatically submit a `game-request` with the exact title, thank the player, tell them completion mail will arrive, and stop game-specific assistance until a reviewed pack exists. `no-game`: ask for the exact game or foreground it.
   A local directory is not a license. The Connector rechecks Server access before frame capture, game context, and choice context, so a removed, expired, copied, or previously installed pack remains inert. Do not preinstall the catalog or remove a pack unless the user explicitly asks.
8. If a Play device is reachable and the question needs live state, take `game-navigator snapshot --no-frame --pretty` first. For shop, skills, equipment, party, whole-loadout readiness, construction, or route/revisit planning, use `game-navigator game-context --purpose <shop|skill-learning|equipment|party|readiness|construction|exploration> --pretty`. For a visible dialogue or branch choice, load [story-choice-assistance.md](references/story-choice-assistance.md) and use `game-navigator choice-context`; this deliberately captures exactly one current frame and joins it with the latest structured state and prior confirmed choices. Request any other frame only when structured data cannot answer, with `snapshot --frame-out PATH` and then open `framePath`. If Play is sleeping, an offline checkpoint may be useful but must be labeled stale.
9. If the game is not confidently matched, ask the user to bring it to the foreground. Do not guess from a similar window title.
10. Load [structured-game-data.md](references/structured-game-data.md) and inspect both `decisionPolicy` and `missingCapabilities` before recommending anything or claiming emptiness. `decisionPolicy` is the Server-authorized, Build- and purpose-scoped slice for this exact request: use its required state, comparison axes, output classes, objectives and fail-closed fallback. If it is absent or a required state is listed as missing, say what is unknown and use only its reviewed fallback; never reconstruct a complete rule set from model memory or stale local files. Load [live-assistance-memory.md](references/live-assistance-memory.md) for bookmarks. A Game Navigation Pack routes Build-scoped adapters and Server-held entity facts and decision rules; player-changing state remains in SQLite and is refreshed from Play.
   - When the user asks which games are adapted, what one game can do, or whether a Mod/plugin would improve it, run `game-navigator compatibility --pretty`. This public catalog is the same source used by the 产品页. `games` are reviewed, installable packs; `inDevelopmentGames` are visible roadmap entries and must never be described as usable or installable. For a supported game, read `control` and `guidance` separately: control depth describes evidence, while guidance status describes how help can be delivered now. Treat its limitations and Mod assessment as the truthful baseline; never average dimensions into a stronger overall claim, and never treat a receiver contract or loader alone as delivered capability.
   - `原版模式` is always the default. Offer a per-game optional observer only after its exact source, license, supported Build, capability delta, stability, multiplayer/anti-cheat impact and complete uninstall path are reviewed. Explain “不装能做什么 / 装后多什么” and wait for the player to decide. Never batch-enable enhancements across games.
11. Give the smallest useful next step. Separate observed, supported, inferred, and unknown. Keep spoilers at light-hint level unless the user asks for more.
   - **Where next / what now**: use `game-context --purpose exploration`. `progress.currentObjective` is the objective from the save: say it, the next step, and 「根据上次存档」. If `progress.unresolvedReason` is `quest-ids-not-yet-mapped`, pick the objective in `decisionPolicy.progression` that matches the saved place, party, key items and the screen, answer with it, and say it is inferred from the last save and the guide. Do not answer "route guidance is not adapted" while a guide is present.
   - **Boss questions**: name the 1–2 most likely nearby bosses from the guide (current chapter first, then the next), with place and a spoiler label; give the `light` hint first and offer `medium` if they want more. Do not ask back which cave or area. State only listed weaknesses; say the rest are not yet verified.
   - **Location**: follow `progress.location.trust`. `trusted`: say the place. `trust-if-screen-matches`: when the frame shows the same place, or the player says they just loaded that save, state the place name as fact with 「根据上次存档」; if the screen disagrees, the screen wins. `confirm-before-stating`: check the frame first. If `placeName` is null, read the name from the screen (map, sign or menu); never invent one.
   - Follow `progress.answerRules` when present.
12. Never collect card numbers, passwords or verification codes in chat, and never pay for the player. Purchases only go through `purchase start`, whose one-time page the player confirms and pays in their own browser; renewal, refunds and orders go through the one-time `account` link.

## Safety

- Play is a sensor, not an input injector. Never simulate gameplay, combat, movement, menus, keyboard, mouse, or controller through Play.
- When the user has explicitly delegated prompt handling in the current conversation and the Agent already has an approved remote-GUI capability, it may dismiss a fully observed, non-binding, non-preference informational interstitial such as “a controller is recommended”. Re-observe immediately afterward and stop at the next real choice. Do not add a generic input endpoint to Play for this convenience.
- Never delegate away agreements/EULAs, permissions, account or login choices, cloud/save conflicts, overwrite/delete, purchases, difficulty, accessibility, graphics, language, controller layout, content filtering, mods/trainers/optional observers, character/build decisions, story choices, scarce resources, or anything irreversible or unclear. Explain those and ask the player.
- Do not automate purchases, uninstalls, trades, messages, trainers, or memory editing.
- Do not change Windows sleep, Modern Standby, wake timers, or power plans.
- Do not write Armoury / vendor caches. ROG settings are read-only; see the `rog-ally` device catalog pack.
- Preserve challenge. Mention WeMod only after ordinary tactics, and never default to invulnerability or one-hit kills.
- Online competitive live advice is off unless the game's published rules allow it.

## Base layer and access boundary

Without an authorized and installed pack, only product explanation, login, pairing, Steam library management, compatibility browsing, access/adaptation requests, and non-game device setup remain available. Do not provide game-specific help through the base Agent as a substitute. The underlying general Agent may know public facts, but those answers are outside this commercial product and this Skill must not use them to bypass the guard.

## Commands

Use the installed CLI `game-navigator`. If it is not on `PATH`, look under the GameNavigator application-support `app/current` directory. All commands accept `--data-dir` and `--server`.
